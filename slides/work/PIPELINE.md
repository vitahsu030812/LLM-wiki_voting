# 投影片製作流程（Graph 版）

> 本文件定義「選民參考簡報」的製作流程。流程本身是一張 graph：
> 每個**節點**產出一個檔案，每個節點後面接一個**檢查關卡**，不通過時沿**退回邊**回到造成問題的節點。
> 另外，大綱的章節結構由 wiki 的**知識圖譜**（頁面＝節點、WikiLink＝邊）產生。

---

## 二、檢查關卡

執行方式（在 git bash）：

```bash
cd "slides/work"
perl build_graph.pl          # 重建知識圖譜
perl build_facts_auto.pl     # 由 wiki 表格產生自動事實卡
perl check.pl A              # 或 B / C / D / all（會先自動重建圖譜與自動事實卡）
perl build_slides.pl         # 第 3 步：依 spec.md 產生 ../2026員林市選舉-選民參考簡報.html
```

`check.pl` 結束碼：0＝通過、1＝有錯誤（ERROR）。警告（WARN）不擋流程，但要在確認時說明。

| 關卡 | 自動檢查 | 人工確認 | 不通過退回 |
|------|----------|----------|------------|
| **A** | ① 每張事實卡的出處頁存在 ② 原文片段確實出現在出處頁 ③ 數值出現在原文片段中 ④ 同一個「鍵」不可有兩個不同的值 ⑤ 五種選票、三個議題都有事實卡 ⑥ 知識圖譜中同一選舉的候選人被樣板連結的次數是否一致 | — | 0（矛盾則先修 wiki） |
| **B** | ① 每頁有且只有一句主張 ② 圖型屬於允許清單 ③ 引用的事實卡存在 ④ 五種選票、三個議題、所有候選人都至少出現一次 ⑤ 總頁數在範圍內 ⑥ 每頁標記的知識圖譜節點存在 | 結構、順序、取捨 | 1 |
| **C** | ① 圖表每一筆數字都對得到事實卡且數值相同 ② 條列 3–7 點、總字數在 40% 版面預算內 ③ 列出候選人時依號次 ④ 禁用評價性字詞 ⑤ 每頁有來源 | 文字、語氣 | 2；缺資料退回 0 |
| **D** | ① HTML 內的圖表數字全部出現在 spec ② 只使用指定色票 ③ 每頁都有頁碼與來源 ④ 版面溢出（`check_layout.js`，在瀏覽器執行） | 最終畫面 | 版面→3；內容→2 |

## 三、知識圖譜怎麼用

- **節點類型**：縣長／市長／議員／代表／里長候選人、議題、選舉結果、總覽、比較分析
- **邊的分類**：
  - `substantive`：頁面內容中的連結（例如議題頁連到候選人）
  - `template`：同一行文字出現在大量頁面（例如每頁底部都連到兩位市長候選人）——**不計入關係**
  - `nav`：連到索引、總覽、選舉結果等導覽頁
- **用途**：
  1. 章節＝各選舉層級（依 `position`）＋議題節點
  2. 議題頁＝議題節點的 substantive 鄰居（哪些候選人談過）
  3. 跨級連線（例如市代轉戰議員）作為「看點」頁的素材
- **中立原則**：同一選舉的候選人篇幅一律相同、依號次排列；圖譜只決定「有哪些章節、誰和哪個議題相關」，不決定「誰比較重要」。

## 四、檔案格式

### facts.md（事實卡）
```
| ID | 鍵 | 值 | 出處頁 | 原文片段 | 原始來源 |
|----|----|----|--------|----------|----------|
| F101 | 員林人口.總數 | 122,148 | 員林市基本資料 | 約 122,148 人（2025年資料） | 員林戶政事務所 |
```
- `出處頁`：wiki 頁面名稱或 alias
- `原文片段`：從出處頁複製的原文（檢查程式會比對）
- `值` 必須出現在 `原文片段` 中

### outline.md（大綱）
```
## S03 員林市基本資料
- 章節: 城市
- 主張: 員林是彰化第二大城，41 里、約 12.2 萬人
- 圖型: hbar
- 節點: [[員林市基本資料]]
- 事實: F101, F102
```

### spec.md（逐頁規格）
```
## S03 員林市基本資料
- 主張: …
- 圖型: hbar
- 依號次: 否
### 圖表資料
| 標籤 | 值 | 事實 |
| 三和里 | 7888 | F110 |
### 條列
- …
### 來源
- …
```

### 計算卡
`出處頁` 填 `計算`，`原文片段` 填算式，檢查 A 會實際計算並比對：
```
| D901 | 計算.2022.市長.差距票 | 982 | 計算 | ={2022.市長.游振雄.票}-{2022.市長.陳秋蓉.票} | — |
| D905 | 計算.議題.長者.據點人數 | 5 | 計算 | =count:F411,F412,F413,F414,F415 | — |
```
自動卡的 ID 會隨 wiki 變動，算式一律用「鍵」引用；人工卡 ID 固定，可直接引用。

### 允許的圖型
`cover column hbar grouped stacked donut matrix timeline units directory li-chart checklist colophon network flow`
（`network`、`flow` 直接由知識圖譜的邊繪製）

### 關卡 C 實際檢查項目（check.pl）
- 規格頁與大綱一一對應；主張、圖型一字不差
- 圖表每列：事實可解析；數字值＝事實值；文字值出現在事實的值或原文中；標記出現在標記事實中
- 標籤中的號次＝候選人實際號次；`依號次` 是／組內 時順序遞增（2022 歷史列不計）
- 大綱「涵蓋」的選舉群組，每位候選人都要出現在圖表
- 條列 3–7 點、每點 ≤ 48 字、合計 ≤ 240 字
- 評價性字詞清單（引號內原文除外）
- 條列／主張／圖說中的數字：三位數以上、含逗號或 % 者必須可溯源（ERROR），小數字不可溯源者為 WARN；可由圖表直接數出的數（各組列數、各標記列數）視為可溯源

### 關卡 D 實際檢查項目
**靜態（`perl check.pl D`）**
- 只使用色票：#BEDEFF #FFF2A7 #FFA500 #930031＋中性色 #2b1a20 #6b5a5f #fffdf6 #e6dccb #f3ecdc #efe6d6 #ffffff；不得用 rgb()/hsl()；不得載入外部資源
- 每頁：頁碼正確、有資料來源頁尾、主張與每一點條列原文都在畫面上
- 圖表每個值都出現在畫面；矩陣 ●○△— 個數與規格相同
- 畫面上的每個數字都必須來自該頁規格（年份除外）
- 評價性字詞

**版面（`check_layout.js`，在瀏覽器執行，桌機與手機寬度各跑一次）**
- 桌機：不壓到頁尾、不超出右邊界、圖表不超出左欄、沒有被截斷的內容
- 手機：不超出視窗寬度、沒有水平捲動
- 兩者：任兩段文字的實際字形外框不得重疊（含 SVG 文字）

**仍需人眼確認**：版面美感、圖表是否容易讀、是否有視覺上的偏重（例如某政黨被強調色凸顯）

## 六、第二份簡報：選前小教學（`DECK=lesson`）

同一套流程與關卡，檔案放在 `lesson/`，產出 `../2026員林市選舉-選前小教學.html`。原選民參考簡報不受影響（不加 `DECK` 時預設 `voter`）。

```bash
cd "slides/work"
DECK=lesson perl check.pl A      # 或 B / C / D / all
DECK=lesson perl build_slides.pl
```

| 項目 | 選民參考簡報（voter） | 選前小教學（lesson） |
|------|----------------------|----------------------|
| 檔案 | `outline.md`、`spec.md`、`facts.md` | `lesson/outline.md`、`lesson/spec.md`、`lesson/facts.md`（另外也載入上一欄的事實卡） |
| 頁數範圍 | 12–22 | 14–28 |
| 關卡 B 涵蓋規則 | 每個選舉群組、每個議題都要出現 | 每一課都要有 `goals`（學習目標）與 `quiz`（小測驗）頁，章節寫「第N課」 |
| 新圖型 | — | `goals`（學習目標）、`cards`（概念卡）、`quiz`（題目＋選項＋收合答案） |
| 新事實引用 | — | `#課:頁名`：值必須逐字出現在該 wiki 課程頁；L 開頭的卡為教學專用事實卡 |
